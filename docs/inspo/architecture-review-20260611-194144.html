The local engine is wired. The flow that matters most can't reach it.

The provider seam, the local-first router, and the anti-bloat cap landed clean (and were already verified). This pass looks one layer out — at consumption — and finds the real gap: eri's computer-use loop (where it types and acts for the user, the wedge) is hard-wired to the cloud and never consults the router, so local-first never reaches it, and those calls also never log for self-improvement.

Problem

run_control_agent takes a pre-picked model: &str (from model_for_mode → always Claude) and posts straight to the proxy. The router, ModelChoice::Local, and LOCAL_CAPABLE_INTENTS are never consulted — so the plan's "local-first for computer-use" is architecturally impossible today.

Solution / leverage

Resolve the control model through the same provider seam: a fast local "can I do this step?" → run on the local engine; self-assess/low-confidence → escalate to Claude through eri's same control surface. The wedge gets free, on-device steps; locality lands in one router.

Deletion test: delete ModelChoice::Local today and control flow is unchanged — proof the seam isn't consumed where it matters.
Worth exploring instrumentation seam

Log every model call — close the self-improvement blind spot

iterate.rs GraphInstr (logs) vs control_agent.rs (no instrumentation hook)

The iterate/brain path wraps calls in GraphInstr and records every on_model_call to eri_graph — the "log" half of the sia loop. But control_agent has no instrumentation hook, so computer-use calls are invisible. The log→critique→refine loop can never learn whether the local engine is good at control if control isn't recorded. Pairs naturally with A: route control through the instrumented path and both gaps close at once.
Speculative delete dead seams

Three intent taxonomies + an orphaned route()

brain_router::Intent (live) · eri_router::IntentKind (unused) · eri_inference::intent::Intent (legacy) · eri_router::route() (orphaned)

brain_router::Intent is the live taxonomy. eri_router::IntentKind and eri_inference::intent::Intent aren't fed to the active routing path, and the older eri_router::route() (RouteRequest→RouteDecision) is never imported by the brain layer. Deletion test: removing them doesn't break iterate/brain. Low-urgency cleanup — confirm no live caller, then delete or document.

Top recommendation

Route computer-use through the provider seam

It's the wedge: eri's value is doing things on your machine, and right now every one of those steps is a forced cloud call that the local engine — even when configured — can't take. Fixing the consumption seam makes local-first real where it matters, and folding control through the instrumented path (B) closes the self-improvement blind spot in the same move. C is free cleanup whenever.
