After — register once behind a Capability trait

flowchart TB
  reg[Capability registry\nname -> handler]:::deep
  reg --> v[Voice]
  reg --> e[Eyes]
  reg --> c[Control]

  pad[morph pad mode] --> reg
  classDef deep fill:#0f172a,color:#fff,stroke:#0f172a;

mode name = capability name = handler key. One registration, not eight edits.

Problem

There's no capability abstraction. Each of the six is hand-wired at every layer; mode names (eyes) diverge from handlers (startGaze), and there's no single place that says "these are eri's capabilities."

Solution

A Capability trait + registry at the sidecar dispatch (lib.rs), with one canonical capability id shared by the pad mode, the bridge, and the handler.

Wins

  • ↳ Adding a capability = one registration
  • ↳ Mode ↔ capability ↔ handler names converge
  • ↳ The pad can enumerate what eri can do
  • ↳ Makes "the pad does everything" real, not aspirational
Deletion test: a registry concentrates the scattered wiring — delete it and the 8-file edit dance returns across every capability. That's the signal it earns its keep.

Honesty check — 5/6 on the pad

Research isn't wired to the morph pad yet

Control, Eyes, Voice, Memory, and Build all reach a real handler from the pad. Research is CLI-only — no morph mode, no Swift case, no pad handler. The "six capabilities" is five on the pad today. The Capability seam above is also the cleanest way to close that gap honestly: register Research once and it lights up in the pad.

Top recommendation

The Capability seam

This is the architecture that makes the product real: the morph pad is supposed to be eri — one surface that does everything — but today each capability is hand-wired 8–15 places and Research isn't even on the pad. A Capability registry turns "add a capability" into one registration and converges mode ↔ capability ↔ handler names. Pair it with B (delete the dead Mercury chain) as easy cleanup; C (Services slimming) falls out of A. The inference path is already deep — this makes the capability path deep too, which is what the pad needs.
