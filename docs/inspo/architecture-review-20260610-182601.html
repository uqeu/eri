Problem

Solution

One resolve_provider(services, choice, tier?) seam: BYOK → proxy → env routing and tier gating live behind a tiny interface.

Wins

  • ↳ 3 shallow reconstructions collapse to 1
  • ↳ One place to mock the provider in tests
  • ↳ web-search bolt-on stops leaking env reads
  • ↳ Tier-aware selection gets a natural home

Problem

Five call sites assemble the same options by hand, and the compaction budget is a constant baked into drive_loop — nothing above the driver can vary it.

Solution

One loop_opts_for(...) factory; promote context_target to a config field set in that one place.

Wins

  • ↳ 5 shallow constructions collapse to 1
  • ↳ Per-tier context window becomes a 1-line change
  • ↳ The driver stays deep; only assembly changes
  • ↳ One place to test option resolution
Note: eri_agent::driver already exposes LoopConfig.context_target as a field — the const lives one layer up, in build_agent. This is the exact seam the pricing-honesty work (true per-tier windows) needs.

the 34-arm rejection list disappears; its 3 real arms already exist as run_build_metered / run_iterate_metered.

Problem

Adding a command means touching a third site — the dead run() rejection list — for zero runtime value (it's #[allow(dead_code)], reachable only from tests).

Solution

Delete run() and repoint its few tests at dispatch; its 3 real arms duplicate logic that already lives in the metered helpers.

Wins

  • ↳ 3 edit sites per command → 2
  • ↳ No more silent catch-all rejection list
  • ↳ One dispatcher to read, not two
Deletion test: deleting run() concentrates nothing — it's a pass-through shadow of dispatch. That's the signal it should go.

Narrow the Services god-object; thin the shallow adapters

eri_coreutils/src/services/mod.rs (Services, 14 fields) · lib.rs dispatch (104 arms) · services/{apply,checkpoints,memory}.rs (shallow)

Before — wide interface, thin body (shallow)

apply

grey = serde marshalling (60–80%) · pale = real call into another crate

After — short interface, deep body (the driver benchmark)

driver.run

run(transport, tools, system, messages, cfg, on_text)

swappable Transport + ToolBox seams · mock-tested end-to-end · new tool = register(), 0 driver edits

handlers depend on a narrow slice (the field they use), not all 14

Problem

The 104-arm string dispatch is fine (idiomatic JSON-RPC), but Services is a 14-field god object passed whole into handlers that use one field, and several adapters (apply, checkpoints, memory) are mostly serde over another crate.

Solution

Let handlers depend on a narrow slice (only what they touch); inline or thin the pass-through adapters. Keep the dispatch shape.

Wins

  • ↳ Handlers testable without the whole registry
  • ↳ Dead _services params disappear
  • ↳ Shallow adapters stop hiding nothing
Caveat: biggest, most diffuse change here — high effort, spread-out locality win. Do it last, incrementally, not as a rewrite.

Top recommendation

Funnel loop assembly & lift the context target

Five hand-built LoopOpts collapse to one factory, and the hard-coded 150K compaction budget becomes a config field set in that one place — which is exactly what makes a true per-tier context window possible. Small, bounded, high locality, and it unblocks the pricing-honesty work. Pair it with candidate 1 (provider acquisition) — both deepen the same inference call path, and the driver underneath is already deep, so neither touches the hard part.
